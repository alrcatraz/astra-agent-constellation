# ADR 0002：为什么位置化部署而非全设备铺开

- 状态：已接受（2026-08）
- 关联章节：[拓扑与角色](../01-topology.md)

## 背景

是否在所有设备（开发机、构建机、网关机、轻量桌面）都部署编码智能体？

## 决策

**只在承担开发/编译/训练/测试功能的机器上部署执行者，不遍布所有设备**。当前：开发机（写码）+ 构建机（按需）。执行者数量随真实工作负载按需增长，没有硬性上限。

## 理由

每个智能体都是「会积累私有记忆的状态机」：

- 多一个智能体 = 多一份配置维护、多一份凭证暴露面、多一个「它知道什么/不知道什么」的同步问题。
- 全设备铺开的边际收益趋近于零：网关机、轻量桌面没有开发工作负载，执行者在那里无事可做。
- 跨设备并行任务罕见，且同步成本最高（多个执行者改同一仓库需要编排协调）。

## 被否决的选项

- **全设备铺开**：维护成本与同步复杂度随数量线性上升，收益不随数量上升。
- **按设备类型预设模板部署**：看似「整齐」，实为过度工程；先痛点后部署更务实。

## 后果

- 执行者只出现在有真实工作负载的平台。
- 新执行者的引入必须由真实痛点触发（如构建-修复循环），而非规划表驱动。
