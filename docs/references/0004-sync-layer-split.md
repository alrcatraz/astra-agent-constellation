# ADR 0004：同步分层——为什么记忆不跨机同步

- 状态：已接受（2026-08）
- 关联章节：[同步分层](../02-sync-layers.md)

## 背景

多个智能体分布在多台机器，各自维护会话与记忆。是否应该让记忆跨机同步，使所有智能体「知道的一样多」？

## 决策

**记忆（记忆库/事实库/会话状态）是本机私有状态，绝不跨机双向同步**。跨机共享只发生在 L1–L5 五层（AGENTS.md / dotfiles / 技能 / 知识库 / 凭证）。

## 理由

- 记忆是「我知道什么」的上下文判断基础；双向同步（如 SQLite merge）是冲突制造机，合并结果不可预测。
- 记忆包含会话局部状态与用户偏好快照，跨机复制会污染各智能体的上下文判断，且扩大隐私暴露面。
- 新机器上的智能体不需要旧记忆——它靠 `git log` + AGENTS.md + README 自举，从零建立对项目的理解。

## 被否决的选项

- **记忆双向同步**：冲突不可控，污染上下文，暴露隐私。
- **记忆单向备份**：可接受但非必需；会话历史已留本机，备份属于运维范畴而非同步范畴。

## 后果

- 同步分层的例外层（记忆）被明确定义为「不跨机」。
- 各智能体的记忆独立演进，互不污染。
