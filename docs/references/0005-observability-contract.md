# ADR 0005：可观察性契约——解耦后错误如何被发现

- 状态：已接受（2026-08）
- 关联章节：[可观察性与审计](../05-observability.md)

## 背景

编排者亲自写码时，用户能观察每一步并发现思路/行为错误。引入独立执行者后耦合降低，用户无法直接看到执行过程——错误思路、错误实现、糟糕的改动记录习惯如何被发现？

## 决策

**透明性从过程转移到契约与痕迹**：接受「看不到直播」，用四个机制替代——决策记录强制、验收标准前置 + 编排者重跑、代码卫生条款、session 回放。

## 理由

- 直播 90% 是噪音；决策记录是信号。强制决策记录让错误思路在报告阶段现形，比观看过程更高效。
- 执行者自报「过了」不可信；编排者重跑验证（CI 等效命令）是客观事实。
- 糟糕的改动记录习惯（如删除内容留「XXX 已删除」占位注释）是代码卫生问题，写进 AGENTS.md 并由 diff 审查拦截。
- session 记录（JSONL）保留完整思考过程，作为兜底审计手段。

## 被否决的选项

- **取消执行者、编排者亲自写码**：回到原点，放弃长任务隔离价值。
- **实时直播执行过程给用户**：认知负担高，且用户无法一直盯着。
- **信任执行者自报**：自报不是事实，违反「重跑才算数」的既有纪律。

## 后果

- 任务 brief 必须包含验证命令与预期（验收标准前置）。
- AGENTS.md 包含代码卫生条款（MUST NOT 留占位注释等）。
- 执行者会话记录保留于工作目录，可按需回放。
