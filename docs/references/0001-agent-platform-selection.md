# ADR 0001：智能体平台选型——双子星与编码执行者

- 状态：已接受（2026-08）
- 关联章节：[拓扑与角色](../01-topology.md)、[双星模式](../06-gemini-pattern.md)

## 背景

本蓝图有两类智能体需要选型：

1. **双子星**——编排者（唯一用户交互入口）与看护者（独立物理机上的恢复者），构成双星模式。
2. **编码执行者**——在承担开发/编译/训练/测试功能的机器上 headless 干活的编码智能体。

两类角色对平台的要求不同，分别决策。

---

## 板块一：双子星 Agent 选型

## 决策

**编排者采用 Hermes Agent（开源智能体框架）——现状，MUST**。

**看护者不要求与编排者同平台**。硬约束是**独立故障域**（见下），而非「同框架」：同框架（独立升级轨道）或异构框架均可，视部署时的隔离成本与维护成本权衡。

## 理由

看护者的本质是「恢复者」：它不需要变成编排者，只需要能把编排者**拉起来**。因此关键不是「和编排者一样强」，而是「**不与编排者共享故障**」——ADR 0003 已保证物理机隔离（不同船），但若两人穿同一件救生衣（同一框架、同一条升级轨道），救生衣破了两个一起沉。

| 故障域层次 | 约束 | 现状 |
|:-----|:-----|:-----|
| 物理机隔离 | 看护者与编排者不同物理机 | ✅ 已有（ADR 0003） |
| 凭证/渠道隔离 | 独立 Bot 账户、不共享登录态 | ✅ 已有（06 §3） |
| **升级轨道隔离** | 看护者跑稳定版，不随编排者升级 | ❌ **缺口——本 ADR 补齐** |

实现「独立故障域」的两种方式都允许：

- **同框架 + 独立升级轨道**：看护者也是 Hermes，但跑稳定版、不跟随编排者升级、配置独立（成本低，隔离中等）。
- **异构框架**：看护者用更简单的栈（如脚本核心 + 轻量 LLM 接口），故障面与编排者彻底解耦（成本高，隔离彻底）。

同构的好处（技能/凭证共享）通过**注册表 + 分层同步**已实现（06 §4），不依赖同框架；「一套升级流程」在同构下反而是缺点（共享风险）。非对称降级中的「编排者临时接管看护职责」是编排者自己的事，不依赖看护者同构。

## 被否决的选项

- **「双子星必须同平台」**：把看护者绑进编排者的故障域——编排者升级事故同时带走看护者，双星模式的恢复承诺破产。
- **编排者与看护者同机双实例**：见 [ADR 0003](0003-guardian-placement.md)——恢复者不能与被恢复者同机，物理隔离是 MUST。

## 后果

- 双子星共享同一套技能库与凭证体系（分层同步见[同步分层](../02-sync-layers.md)）。
- 看护者物理机就位后，以同框架镜像部署，职责可平移。

## 板块二：编码执行者选型

## 决策

**编码执行者采用 OpenCode（开源 headless 编码智能体）**。

## 理由

执行者有四条硬约束，OpenCode 全部满足，逐条对照如下。

### 硬约束一：复用自建模型网关（零新增订阅）

执行者必须能使用现有的统一模型网关（OpenAI-compatible 端点），不引入第二套模型凭证。

| 方案 | 模型绑定 | 能否直连自建网关 |
|:-----|:---------|:----------------|
| **OpenCode** | 任意 OpenAI-compatible provider，`baseURL` 指向网关 | ✅ 一行配置 |
| Claude Code | Anthropic 生态 | ❌ 需兼容层或新订阅 |
| OpenAI Codex | OpenAI 生态 | ❌ 绑定 |
| Aider | 任意 API key（自带 key 管理） | ⚠️ 可接，但凭证分散管理 |
| Gemini CLI | Gemini 生态 | ❌ 绑定 |
| Qoder CN CLI（阿里） | 千问系为主 | ❌ 绑定阿里生态 |
| CodeBuddy CLI（腾讯云） | 混元/DeepSeek/智谱/Kimi（内置列表） | ❌ 内置列表，非任意端点 |
| MarsCode / Comate / CodeGeeX | 各自厂商模型 | ❌ 绑定 |

### 硬约束二：开源可审计

执行者跑在受控机器上、进 git 审计链，必须代码可查、无遥测绑架。

- **OpenCode**：开源（GitHub），本地运行，可审计 ✅
- Claude Code / Codex / Gemini CLI：闭源或绑定生态 ❌
- 全部国产方案（Qoder CN CLI / CodeBuddy / MarsCode / Comate / CodeGeeX 客户端）：闭源 ❌
- 例外注记：CodeGeeX 的**模型**开源可自托管，但客户端闭源，仍不满足审计要求。

### 硬约束三：headless 无人值守

| 方案 | headless 能力 |
|:-----|:--------------|
| **OpenCode** | ✅ `opencode run` 非交互执行，`--continue` 跨天续跑 |
| Claude Code | ⚠️ 有但绑定自家生态 |
| Qoder CN CLI | ✅ 有 Remote Control 模式、Print 模式 |
| CodeBuddy CLI | ⚠️ 部分（Craft 智能体） |
| MarsCode / Comate / CodeGeeX | ❌ IDE 插件形态，无独立 CLI |
| Aider | ✅（结对模式为主） |

### 硬约束四：ACP 协议开放

执行者需支持开放协议，使 IDE 等客户端可通过 ACP 连接。

- **OpenCode**：原生支持 ACP ✅
- Claude Code：支持 ACP ✅
- Qoder CN CLI：支持 ACP ✅
- Codex / CodeBuddy / MarsCode / Comate / CodeGeeX：私有或无公开协议 ❌

### 综合对照

| 维度 | **OpenCode** | Qoder CN CLI | CodeBuddy CLI | MarsCode/Comate/CodeGeeX |
|:-----|:-------------|:-------------|:--------------|:-------------------------|
| 模型绑定 | 任意 OpenAI-compatible，baseURL 直连自建网关 | 绑定阿里生态 | 内置列表（腾讯云托管） | 绑定各自厂商 |
| 开源可审计 | ✅ | ❌ | ❌ | ❌ |
| headless | ✅ run + continue | ✅ Remote Control | ⚠️ 部分 | ❌ |
| ACP | ✅ | ✅ | ❌ | ❌ |
| 凭证成本 | 零新增（复用网关） | 新增阿里云 key | 新增腾讯云 key | 新增各家 key |

**四条硬约束逐条过**：国产方案中形态最接近的 Qoder CN CLI（CLI + ACP + headless 齐全）在「模型绑定」与「开源审计」两条硬约束上不满足；其余国产方案均以 IDE 插件为主，缺 headless 与 ACP。结论不受国产方案影响，**执行者仍采用 OpenCode**。

## 被否决的选项

- **Claude Code**：模型栈、凭证栈与现有设施（模型网关 + 凭证库）不兼容，引入新订阅；闭源。
- **OpenAI Codex / Gemini CLI**：绑定各自厂商生态，不符合模型复用。
- **Aider**：可接任意模型但为结对模式（pair-programming），非 headless 执行者形态；凭证分散。
- **Qoder CN CLI**：形态达标（CLI/ACP/headless），但绑定阿里模型生态、闭源——两条硬约束不满足。若未来放开任意 baseURL 且开源，需重新评估。
- **CodeBuddy CLI**：模型为内置列表（含腾讯云托管的 DeepSeek），非任意端点；闭源。
- **MarsCode / 文心快码 Comate / CodeGeeX**：IDE 插件形态，无独立 CLI，不符合执行者定义。
- **官方 multi-agent 框架**：尚在 roadmap 未落地；且本蓝图不需要执行者间的复杂协作。
- **自研编码智能体**：成本过高，无必要。

## 关于 Marvis 的澄清

**Marvis（马维斯）不是编码智能体**——它是腾讯的**操作系统级 AI 助手**（Windows/macOS/Android/iOS 客户端），能力方向为本地大模型、文件智能整理搜索、手机远程控制电脑、一句话改系统设置等，与编码执行者不同赛道。它与腾讯云 CodeBuddy 是两款不同产品，不应混淆。本 ADR 不将其列入执行者候选；其「本地模型、文件 0 上传」的隐私设计作为趋势观察记录。

## 后果

- 执行者配置为 `opencode.json` + `baseURL` 指向模型网关。
- 执行者纪律（permissions、doom_loop）由 OpenCode 配置承载（见[纪律传导](../04-harness.md)）。
- 若未来模型网关不再是 OpenAI-compatible，或 OpenCode 收紧 baseURL 自由度，或国产方案放开模型绑定并开源，本 ADR 需重新评估（ADR 存在的意义：决策可被新证据推翻）。
