# 采纳路径

本蓝图不要求一次性全量落地。按四个阶段推进，每个阶段有明确的验收标准；**Phase 0 先行是整个方案的命门**——事实层没立起来之前，多雇一个智能体只是多一份混乱。

## Phase 0：同步地基（先行，命门）

目标：事实层就位，让后续任何智能体都有「规矩可依」。

| 任务 | 验收标准 |
|:-----|:---------|
| 每个活跃仓库写入 `AGENTS.md`（构建禁令、验证命令、代码卫生条款） | 执行者能仅凭 AGENTS.md 知道项目规矩 |
| dotfiles 仓库建立，全局配置 git 化 | 新机器可一键拉取部署 |
| 技能仓库双副本同步机制运行 | `astra-lifecycle-sync --check` 干净 |
| 需共用的工具服务网络化（如 MarkItDown → SSE） | 非宿主进程可连端点 |
| 凭证库盘点，配置中零明文凭证 | grep 检查通过 |

**验收**：新机器从零开始，按 L1→L5 顺序部署后能完成一个真实任务。

## Phase 1：第一个执行者（开发机）

目标：验证「编排者 → 执行者 → 验收」全链路。

- 在开发机部署 OpenCode，接入模型网关（baseURL）。
- 用**一个真实 feature**（如 astra-aigate 的某个实现）走全流程：brief → 执行 → 决策记录 → 编排者重跑验证 → diff 审查 → 用户确认。
- 配置 permissions 硬门（git push deny、doom_loop）。

**验收**：feature 落地且通过 CI 等效验证；执行者全程未直接与用户对话。

## Phase 2：下一个执行者（构建机，按需）

目标：消除跨机构建-修复循环的传输成本。

- **先出现痛点再部署**：确认开发机上反复出现「构建-修复」循环（如 Next.js 编译只允许在构建机）。
- 在构建机部署 OpenCode，经 ssh 由编排者调用。
- 大文件传输走流式管道（`podman save | ssh podman load`），不用 scp 大 tar。

**验收**：构建-修复循环在一个编排者会话内闭环，无大文件传输卡死。

> **按需扩展**：出现新的真实工作负载（如学校工作站的模型训练/测试、新的编译目标）时，按同一模式部署新的执行者——先痛点后部署，不预先铺开。

## Phase 3：看护者上岗（双星模式）

目标：恢复能力独立于主星机器。

- 前置条件：**看护星独立物理机就位**（当前未就位，正在准备）。
- 部署看护星（同框架独立升级轨道或异构栈均可，见 [ADR 0001](references/0001-agent-platform-selection.md) 板块一），配置 agent 注册表仓库。
- 健康检查 cron 就位，恢复流程按注册表定义验证（模拟主星宕机演练，见[演练剧本](09-game-day.md)）。

**验收**：模拟主星宕机，看护星能在预期时间内恢复主星（演练通过——变体 A 必过，见[演练剧本](09-game-day.md) §0/§6）。

## 每阶段之间的门

- 前一阶段验收未通过，不得进入下一阶段。
- 每个阶段完成时更新 agent 注册表（若已存在）与文档站。

## 时间与规模建议

- Phase 0 建议 1–2 周内完成（纯配置 + 文档，无代码风险）。
- Phase 1 在第一个真实 feature 时自然发生，不刻意造任务。
- Phase 2/3 仅在痛点出现或物理机就位时触发，不预设时间表。
