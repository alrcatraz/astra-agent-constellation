# 可观察性与审计

引入独立执行者后，用户不再直接看到它的执行过程（直播变成黑盒）。本蓝图要求：**透明性从过程转移到契约与痕迹**——用户失去的是直播，得到的是可回放 + 契约对照。

## 1. 四类问题与对策

| 问题 | 机制 | 谁执行 |
|:-----|:-----|:-------|
| 错误思路 | **决策记录强制**：任务完成时输出「改了什么、为什么、放弃了哪些替代」 | 执行者产出，编排者审查 |
| 错误实现 | **验收标准前置 + 编排者重跑**：brief 写死验证命令与预期，执行者自报不算数 | 编排者 |
| 糟糕的改动记录习惯 | **代码卫生条款**（AGENTS.md）：删除不留占位注释、注释只解释为什么 | 编排者 diff 审查 |
| 兜底审计 | **session 回放**：执行者完整会话记录（JSONL）可审计 | 编排者/用户按需 |

## 2. 决策记录（错误思路的现形点）

- **MUST**：执行者每次任务完成时输出决策记录（decision record），包含：改了什么、为什么这么改、考虑了哪些替代方案、放弃的理由。
- **MUST**：决策记录随任务报告一起返回编排者，编排者审查其与任务 brief 的一致性。
- 理由：思路错误在决策记录里现形，比看直播更高效——直播 90% 是噪音，决策记录是信号。

## 3. 验收标准前置（错误实现的拦截点）

- **MUST**：任务 brief 中写死验证命令与预期结果（如 `npx tsc -p tsconfig.typecheck-core.json` 零新增错误、服务冒烟 16/16）。
- **MUST**：验证命令失败时，执行者停下汇报原始输出与根因初判，**不得修改命令或预期结果来制造通过**——「改命令凑绿」是纪律违规。
- **MUST**：编排者重跑验证，执行者自报「过了」不作为结论。
- **MUST**：编排者对执行者的改动做 git diff 审查（对照任务 brief 的范围声明）。

## 4. 代码卫生条款（改动记录习惯）

写入项目 AGENTS.md，编排者在 diff 审查时逐条核对：

- **MUST NOT**：删除的内容留占位注释（如「XXX 已删除」）——删了就是删了，git 历史保留证据。
- **MUST NOT**：注释记录「删了什么 / 改了什么」——注释只解释「为什么」。
- **MUST NOT**：留下垃圾 TODO（无归属、无理由的 TODO 视为未完成）。
- **SHOULD**：注释解释设计意图与约束，而不是复述代码。

## 5. 审计回放

- **SHOULD**：执行者的会话记录（JSONL）保留在项目目录，按需可回放完整思考过程。
- **MAY**：用户要求时，编排者拉取原始 transcript 供用户审查。
- **MUST NOT**：执行者的会话记录包含凭证值（凭证只经环境变量注入，不被记录）。

### 5.1 会话记录格式（兜底审计）

执行者会话记录为 JSONL，每行一个事件，最小字段：

```json
{"ts": "<RFC3339>", "event": "tool_call|tool_result|user_msg|assistant_msg|decision", "agent": "<agent-ref>", "detail": "<引用或摘要>"}
```

- **MUST NOT**：`detail` 中出现凭证值、真实密钥、内嵌令牌（凭证只经环境变量注入）。
- **SHOULD**：决策事件引用决策记录文件而非复制正文（避免双写漂移）。
- **SHOULD**（输入完整性）：模型可见的输入可追溯——任务派发输入（task-brief、prompt、注入的指令层）以文件引用或事件形式可回放，至少满足「给定同样输入可重放同一决策路径」（dsh 的 "Model-visible means logged" 输入侧审计不变量）。不要求复制正文（避免凭证/大文本入审计），但**必须能定位输入真源**。

### 5.2 工具门禁审计事件（结构化操作记录）

门禁（03 §3.3）对每次工具调用产生结构化审计事件，与执行者会话记录**分离**（门禁审计 = 操作事实，会话记录 = 思考过程）。格式：

```json
{
  "ts": "<RFC3339>",
  "agent": "<agent-ref>",
  "service": "<service-name>",
  "scope": "<resource>:<action>",
  "action": "call|grant|deny|revoke|register",
  "result": "ok|denied|error",
  "ref": "<request-id>"
}
```

- **MUST**：每次门禁调用记一条（`action: call`），含 agent/service/scope/result。
- **MUST**：鉴权拒绝记 `action: deny` + `result: denied`——审计拒绝与放行同等重要（失败审计）。
- **MUST**：scope 变更/服务注册记 `grant|revoke|register`——权限变化可追溯。
- **MUST NOT**：审计事件含凭证值、请求体内容（只记元数据 + `ref`，正文按需另存）。
- **SHOULD**：`ref` 关联门禁请求与执行者会话记录（跨系统追溯）。
- **留存**：门禁审计 ≥ 注册表变更历史保留期（落 git 的事件永久；服务端事件按部署约定，默认 90 天）。

## 6. 可观测性仪表

| 指标 | 数据源 | 用途 |
|:-----|:-------|:-----|
| 任务验收通过率 | 编排者验收记录 | 执行者质量趋势 |
| 决策记录完整性 | 每次任务报告 | 思路质量 |
| diff 审查发现数 | 编排者审查记录 | 执行者纪律水平 |
| 会话记录留存 | 执行者工作目录 | 兜底审计 |
